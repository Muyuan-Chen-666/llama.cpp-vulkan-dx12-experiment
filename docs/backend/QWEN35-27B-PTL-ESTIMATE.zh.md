# Qwen3.5-27B 各版本可用性估算

日期：2026-10-18。GPT-6.1 Sol 编写。**这是容量估算，未下载或实跑 27B，不能当作性能评测。**

## 估算前提

沿用本机 32GB 物理 RAM、BIOS 8GB 预留、Vulkan 13728MiB 可见额度。专用显存和共享内存来自同一物理 RAM，导入显存也占当前 Vulkan 额度，不能简单相加。模型按 Qwen3.5-27B 文本部分估算。

官方配置为 64 层，其中 16 层 full attention、48 层 linear attention；full attention 有 4 个 KV 头、head_dim=256。27B 是密集主干，不能用 35B-A3B 的激活参数量或 23 token/秒直接推断它更快。

## 上下文额外开销

仅计算 full-attention KV 数据，f16 的理论基础开销为 `16 × 4 × 256 × (K+V 两份) × 2 字节 = 65536 字节/token`：

| 上下文 | f16 K/V | q8_0 K/V 理论量级 |
| --- | ---: | ---: |
| 8K | 0.50GiB | 约 0.27GiB |
| 16K | 1.00GiB | 约 0.53GiB |
| 32K | 2.00GiB | 约 1.06GiB |
| 64K | 4.00GiB | 约 2.13GiB |

另有约 144MiB 的单份基础 DeltaNet 状态量级、卷积状态、工作缓冲、输入 embedding、提示缓存/快照、驱动与系统开销；不能只比较 GGUF 文件和总 RAM。多会话、图像、图像编码器均会继续增加占用。

按 32K f16 KV 和约 0.5–1GiB 工作/状态开销，当前 Vulkan 额度大约只能给 GPU 主权重留下 10.4–10.9GiB。输入 embedding 的 CPU 放置可减少部分 GPU 需求，但其具体量化和大小需读取实际 GGUF 后才能确定。因此 IQ3 级较有希望大量/全部放 GPU，Q4 级通常需要部分 CPU 层。

## 速度预期与试验顺序

本机没有 27B 密集模型基准。每 token 需要访问的权重远多于当前稀疏 MoE 的已选专家，通常应按**个位数 token/秒的量级**规划，再用实测修正；不能承诺延续 20 token/秒以上。不同量化格式的解码成本、CPU 放置比例、电源、温度和上下文会改变结果，当前证据不足以给每一种格式标出可靠 token/秒。

容量/GPU 放置优先时，先试 UD-IQ3_XXS；希望比较较高精度输出时，再试 IQ4_XS 或 Q4_K_M。Q5 及以上不优先考虑本机日常对话。量化质量需要真实任务 A/B，表格不保证某种量化的答案更正确。

GPTQ/AWQ、原生 FP8 不属于当前 GGUF 路径，不能直接用这个启动器，也不能假设同一显存补丁自动适配。视觉任务还需约 0.86GiB 的 F16 投影器及图像计算缓冲，本表未做视觉运行验证。
